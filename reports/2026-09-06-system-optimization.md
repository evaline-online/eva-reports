## 🛠️ Детальный перечень выполненных работ

* **Решение**:
  * Физически перенесены на Рабочий стол ([`~/Desktop/`](file:///home/evabot/Desktop)):
    * `AGENTS.md` — глобальные системные инструкции для ИИ-агентов.
    * `mcp-servers.json` — мастер-конфигурация 21 MCP-сервера.
    * `eva-link/` и `ssh-bridge/` — утилиты туннелирования и сетевые скрипты.
    * `remote_evabot_server/` — очищенная папка удаленного доступа.
  * В корне домашней папки (`~`) настроены прозрачные символические ссылки (`symlinks`), чтобы CLI и агенты продолжали считывать их по стандартным системным путям.
  * Утилита синхронизации [`sync-mcp`](file:///home/evabot/.local/bin/sync-mcp) обновлена: теперь мастер-копия генерируется сразу на Рабочий стол в `~/Desktop/mcp-servers.json` с поддержкой обратной совместимости.

### 2. Надежность памяти: 8 ГБ Swap на `/data`
* **Проблема**: В системе было **0 байт Swap**. При параллельном запуске браузера Chromium, нескольких агентов и LiteLLM с 85+ моделями существовал риск аварийного закрытия процессов через Linux Kernel OOM Killer.
* **Решение**:
  * На скоростном дополнительном NVMe-диске создан файл подкачки: [`/data/swapfile`](file:///data/swapfile) размером **8.0 ГБ**.
  * Выставлены права безопасности `chmod 600`, выполнена инициализация `mkswap` и активация `swapon`.
  * Добавлена постоянная запись в [`/etc/fstab`](file:///etc/fstab) с параметрами `sw,nofail 0 0`.
* **Текущее состояние памяти**:
  * ОЗУ: **31 ГБ** (доступно ~23 ГБ).
  * Swap: **8.0 ГБ** (активен, готов к пиковым нагрузкам).

### 3. Интеграция диска `/data` и ротация логов (Logrotate)
* **Проблема**: Дополнительный SSD-диск на 49 ГБ не использовался (занято 20 КБ), а логи служб в `/var/log` росли без автоматической ротации.
* **Решение**:
  * На диске `/data` созданы рабочие каталоги для разгрузки системного раздела:
    * [`/data/backups`](file:///data/backups) (для резервных копий проектов и баз SQLite).
    * [`/data/cache`](file:///data/cache) (для тяжелых кэшей).
    * Владелец: `evabot:evabot`.
  * Настроен файл правил ротации [`/etc/logrotate.d/evabot`](file:///etc/logrotate.d/evabot):
    * Ротация логов `evabot-brain*.log` и `omniroute*.log`.
    * Параметры: еженедельно, хранение 4 поколений, сжатие gzip (`delaycompress`), `copytruncate`, порог `maxsize 50M`.
    * Dry-run тест успешно пройден (`exit code 0`).

### 4. Исправление сетевого стека и DNS Tailscale
* **Проблема**: В `tailscale status` отображалась постоянная ошибка здоровья: `Tailscale failed to fetch the DNS configuration of your device: exit status 1`.
* **Причина**: Устаревший комментарий в `/etc/resolv.conf` сбивал автоопределение резолвера в Tailscale, заставляя его обращаться к `resolvctl` с синтаксисом `openresolv` (`-i`).
* **Решение**:
  * Восстановлена корректная символическая ссылка [`/etc/resolv.conf`](file:///etc/resolv.conf) ➔ `/run/systemd/resolve/stub-resolv.conf`, управляемая `systemd-resolved`.
  * Перезапущен цикл проверки Tailscale.
* **Результат**: Ошибка полностью устранена. `tailscale status` сообщает: **100% Clean (0 warnings)**.

---

### 5. Оптимизация ИИ-слоя (Omniroute / LiteLLM)
* **Проблема**: В конфигурации `/opt/omniroute/config.yaml` были активны 19 моделей Hugging Face без валидного токена (`HF_TOKEN=hf_placeholder`), что приводило к постоянным ошибкам 401/429 и спаму в журнал ошибок (файл вырос до 2.3 МБ).
* **Решение**:
  * Все неактивные модели Hugging Face закомментированы и выведены из роутера.
  * Файл [`/var/log/omniroute.error.log`](file:///var/log/omniroute.error.log) безопасно сброшен с 2.3 МБ до 0 байт.
  * Исправлен синтаксис в [`/opt/omniroute/config.yaml`](file:///opt/omniroute/config.yaml).
  * Служба `omniroute.service` перезапущена.
* **Результат**:
  * `http://127.0.0.1:20128/health/liveness` ➔ **HTTP 200 OK ("I'm alive!")**.
  * Доступны **122 проверенные рабочие модели** (OpenRouter, Groq, Gemini, Cerebras и др.).
  * Спам ошибок в логах прекращен.
